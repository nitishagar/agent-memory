Self-host sync

One server, many teammates. The server holds an immutable union of every member's records; clients merge it locally. Sync is TLS-only with certificate pinning — there is no cleartext mode and no proxy bypass.

1. Start the server

$ amem sync-server --dir /srv/amem --init-cert
{"fingerprint":"SHA256:…"}
$ amem sync-server --dir /srv/amem --listen 0.0.0.0:8443

Share the fingerprint with your team out of band. Run it under systemd, docker, or plain nohup — it is a single static-ish binary.

2. Connect clients

$ amem sync --endpoint https://sync.internal:8443 --trust-new
{"uploaded":128,"downloaded":431,"duplicates":0,"conflicts":0,"quarantined":0,"branches":1}

First contact pins the server certificate (TOFU, stored with mode 0600). Later syncs refuse on pin mismatch. Omit --trust-new after the first run.

3. How merges work

SituationBehavior
Same id, same bytesDeduplicated silently.
Same id, different bytesBoth kept; the loser is flagged in amem branches with reason: "id". Nothing overwrites.
Corrupt / oversize / future-dated envelopeQuarantined with a reason, hidden from recall, flagged in export. amem unquarantine restores.
Server restored from an old backupClients refuse with a rollback error — restore the server, then sync again.
Server wiped and re-createdClients refuse with a divergence error; re-run with --recover --confirm to adopt the new union and re-push.

4. Operate

  • Back up /srv/amem (the union is one SQLite file plus the cert).
  • To move hosts, copy the directory — the generation id moves with it, so clients keep syncing.
  • To start over, delete the directory and re-run --init-cert; every client then needs one --recover --confirm.
A hosted sync tier (no server to run) is planned as a paid option later. Self-hosted sync stays free and open source forever.
