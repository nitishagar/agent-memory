Security model

amem is local-first: capture, storage, and recall never leave your machine unless you run sync. This page states exactly what sync trusts, what it verifies, and what it deliberately does not do yet.

What sync guarantees

  • TLS-only transport. http:// endpoints are refused, never attempted. There is no cleartext mode and no proxy support (proxy env vars fail closed).
  • TOFU server pins. First contact pins the server certificate byte-for-byte (sync_pins.json, mode 0600, atomic writes). Later connects trust only the pinned bytes — no CAs, no PKI. Mismatches refuse with both fingerprints shown. Use --expect-fingerprint to verify first contact in scripts.
  • Payload integrity. Every envelope hash is verified on upload-build, server-post, and download-apply. Corrupt, oversize, malformed, future-dated, and clock-inconsistent envelopes quarantine with reasons — never silently applied, never silently dropped.
  • No silent merges. Same-id divergences branch (both versions kept); generation changes and rollbacks refuse loudly; recover is explicit (--recover --confirm) and reports what it will push.
  • Local lockdown. Store, server DB, pins, and keys are created 0600/0700 from the first byte. Secrets are redacted at capture, before disk.

What sync trusts (threat model)

  • The server and your teammates are trusted for integrity. Envelopes are unsigned and unencrypted at rest on the server: a malicious server or peer can read, withhold, or forge record metadata. Payload hashes catch corruption, not malice.
  • The server has no client authentication. Anyone who can reach the port can read and write the whole union. Non-loopback binds require --public --confirm; do not expose the port beyond your team without an authenticating front proxy.
  • There are no quotas or rate limits. Request sizes are capped, but request counts, series counts (past a fan-out guard), and database growth are not. A malicious client can fill the server disk.

Planned hardening (not in MVP)

  • Signed envelopes (per-device keys; the real fix for peer forgery).
  • End-to-end encryption envelope (the e2e_envelope field is reserved).
  • Server auth (bearer minimum), per-device quotas, rate limiting.
  • Union transparency (signed checkpoints so selective withholding is detectable).
Found a hole in what IS promised above? Open a security advisory on GitHub — transport, pinning, quarantine, and merge-integrity bugs are treated as P0.
